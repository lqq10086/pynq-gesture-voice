# PYNQ 手势与语音交互系统技能包

本技能包围绕本次参赛作品——基于 PYNQ 的手势与语音交互系统整理，涵盖项目开发中的架构接入、任务分配、工程模板、EDA 构建和问题排查。贪吃蛇工程是独立的跨项目复用案例，用来展示这些方法在另一类应用中的使用。团队已有跨板卡使用经验；用于新项目时，按实际板卡、硬件接口和任务填写参数。

## 技能入口

| 技能 | 适用场景 | 使用方法 | 使用条件 |
| --- | --- | --- | --- |
| [通用 PYNQ 工作流程](pynq-overlay-workflow/SKILL.md) | 新应用接入、Overlay 加载、PS/PL 接口与寄存器检查 | 按入口说明记录设备和工程信息，填写接口契约，依次进行文件检查、硬件接入和验证 | bit、HWH、IP、地址、时钟和复位按目标工程填写；寄存器读取遵循当前接口定义 |
| [任务提示词](fpga-task-prompts/SKILL.md) | 拆分任务、约定接口、报告复核、板端诊断与交接 | 从 `prompts/` 选择模板，填写目标、输入、可修改文件和验收方式 | 接口与验收条件需要填写清楚；只读复核不修改工程 |
| [工程骨架与模板](fpga-project-skeleton/SKILL.md) | 新建 FPGA/PYNQ 工程，整理源码、仿真、报告和交接材料 | 复制 `work_sample/`，或用 `tools/bootstrap_project.py` 创建工程骨架 | 器件、引脚、源文件和板端接口按目标工程填写；环境探测使用同级的 `eda-script-runner` |
| [EDA 脚本](eda-script-runner/SKILL.md) | 探测工具、创建工程、综合实现和查看时序 | 先用 `tools/eda_env.py` 检查环境，再通过 `tools/run_tcl.py` 选择脚本与参数 | 需要与脚本匹配的工具和输入文件；涉及板端操作时先完成设备移交 |
| [踩坑清单](fpga-pynq-pitfalls/SKILL.md) | 工程构建、上板、模型、测量或协作遇到问题 | 按 `SKILL.md` 的症状索引，在 `pitfall-list.docx` 查找对应现象、定位和处理步骤 | 根据当前版本和接口条件选择条目；需要设备手册或实物确认时按实际条件处理 |

Markdown 文件可直接阅读，也可将各技能目录放入支持技能发现的工具中。开始一个新的 PYNQ 应用时，建议依次使用“任务提示词 → 工程骨架 → 通用 PYNQ 工作流程 → EDA 脚本”；遇到问题时按症状查阅踩坑清单。

## 跨项目复用案例：贪吃蛇

本次参赛作品是手势与语音交互系统。贪吃蛇是独立工程，作为跨项目复用案例，用于展示 PYNQ 接入方法在另一类应用中的使用。

| 内容 | 本次参赛作品：手势与语音交互系统 | 跨项目复用案例：贪吃蛇 |
| --- | --- | --- |
| 共用方法 | PYNQ 环境、处理器系统配置、Overlay 接入、PS/PL 协同与硬件接口核对 | 沿用同样的平台配置与接入方法 |
| PL 功能 | 摄像头采集、视频显示通路和手势网络计算 | 按键消抖、事件队列与数码管扫描 |
| PS 功能 | 手势处理、交互控制与应用界面 | 游戏控制与状态传输 |
| 验证方式 | 构建报告、运行状态及现场画面与手势确认 | Overlay 加载、外设校准、按键和显示交互记录 |

两个工程使用的处理器系统配置参考文件内容一致，并分别在工程创建过程中调用。团队结合两个项目中的 Overlay、寄存器接入和调试经验，整理出通用 PYNQ 工作流程。案例来源、配置文件哈希和验证记录见 [跨项目复用案例](evidence/reuse_case/README.md)。

## 已验证的使用效果

- **通用 PYNQ 工作流程：** 包内的接口检查脚本完成 19 项隔离软件测试；技能中的项目案例保留了 Overlay 加载和外设验证记录。见 [验证记录](pynq-overlay-workflow/verification/README.md)。
- **任务提示词：** 用接口、目标文件和验收条件组织任务；诊断模板按采集、算法、界面和显示分层检查。
- **工程骨架：** 在空目录生成源码、仿真、构建、板端和报告目录，并生成环境清单。
- **EDA 脚本：** 使用统一入口创建小型 RTL 工程；项目路由结果和测试日志见 [工程案例](evidence/cases.md)。
- **踩坑清单：** 汇总工程停止、模型前处理、时序和接口等问题，按现象与阶段索引查找。
