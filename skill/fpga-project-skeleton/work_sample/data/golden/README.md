# data/golden —— 黄金参考

这里是「标准答案」，比对时以它为准。放错东西的代价最大：拿被测代码自己的输出当参考，会让整条验证链失效。

## 放什么

- 与硬件实现**不同来源**的参考结果：浮点模型、PC 侧 NumPy 实现、厂商工具的输出。
- 生成参考所用的脚本、参数、输入清单。
- 逐层中间张量（如果要做逐层比对）。

## 不能放什么

- 被测硬件自己的输出（同源自证，等于没测）。
- 无法重新生成的二进制（没有生成脚本的参考，过一版就废）。
- 从网上抓来的「看起来对」的结果。

## 命名

按「实现-精度-层」命名，避免歧义：

```
fp32-pyref-all.png
fp32-pyref-layer05.bin
int16-vitisref-layer05.bin
```

## 管理

| 问题 | 做法 |
| --- | --- |
| 凭什么信这份参考是对的 | 生成脚本可重跑、输入可查、与他人实现比对过一次；三条缺一条就标「未交叉验证」 |
| 精度不同怎么比 | 浮点参考与定点参考分开存，比对时按层设容差，不混成一张图 |
| 参考更新后旧版怎么办 | 保留旧版并加日期后缀，在 `manifest.csv` 写清为什么更新 |
| 参考与被测输入的对应关系 | `manifest.csv` 一行一条：参考文件、生成脚本、输入文件、输入 sha256 |

## 最低要求

每个参考文件配一行说明：由什么代码、什么输入、什么精度、什么时候生成、谁验证过。
没有这一行，它只是一个普通二进制文件，不是参考。
