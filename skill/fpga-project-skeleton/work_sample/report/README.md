# report 目录说明

每一轮构建、每一次优化、每一份证据，都在这里留一份文件。目录里的 `.docx` 是实例与模板：

| 文件 | 什么时候写 |
| --- | --- |
| `design-report.docx` | 设计定稿后写一次，之后随版本更新 |
| `optimization-log.docx` | 每做一次优化写一份，记优化前后的对照与判断依据 |
| `verification-log.docx` | 每次验证写一份，按证据层（仿真 / 实现 / 板端 / 实测）分开记 |
| `hardware-gate.docx` | 每换一次 bit 或 DCP 写一份，记录身份、时序、资源、CDC/DRC 与是否允许部署 |
| `handoff.docx` | 交接或提交前写一份，未做的一律写 NOT_RUN |

规则：
1. 报告里的每个数字都要能指回一份原始文件或一次测量的条件，不要只写结论。
2. 失败与被否决的方案也要留，写清为什么不采用。
3. 一份报告对应一次构建或一次测量；换了比特流、换了模型、换了输入，旧报告不能再当作新结论使用。
4. 需要 PDF 时从 Word 直接导出，不要把同一份内容维护成两份。
