# tests/

放能自动跑的检查，不放人工记录。

典型内容：

- `test_*.py`：用 pytest 写的单元检查，跑得快、不依赖硬件。
- `run_checks.ps1` 或 `run_checks.sh`：一次跑完全部检查并返回非零退出码，便于 CI 与 agent 判断。
- 仿真用例的清单：哪个 testbench 对应哪条需求，一行一条。

规则：

- 每个检查都要能在没有板卡、没有网络的机器上跑完；需要硬件的检查单独放 `board/`。
- 检查失败要打印"期望 / 实际 / 出处"，不打印一大段日志让人自己找。
- 检查与设计同版本管理；改了接口契约，先改检查再改实现。
- 不把生成的波形、日志、覆盖率数据放进这里，它们属于 `build/`。
