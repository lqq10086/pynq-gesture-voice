适用场景：出现可观察的异常（报错、画面异常、数值不对、进度停滞），或要在开工前确定该确认哪些前提时。不适用于"从零设计一个新功能"。


# FPGA / PYNQ 工程踩坑排查

这是一份按阶段与症状组织的排查清单，不是教程。它的用法是：拿到一个说不清原因的现象，
先找到对应条目，做它给的**一个**区分实验，用结果决定下一步；不要一次改多处。

完整条目（每条含现象、触发条件、怎么发现、怎么定位、怎么处理、适用边界）在
`pitfall-list.docx`。本文件只给索引与判断方式。

## 什么时候打开

- 工程停在同一处反复重试，或者 agent 一直"在做"但没有可核对的产物。
- 一个具体现象反复出现：花屏、错位、半帧、无数据、寄存器读回固定值、帧率不达标。
- 数字已经拿到，但不确定能不能这么比。
- 交付前要确认哪些前提还没确认。

不适用：需要具体器件手册才能回答的问题、需要厂商支持的缺陷、纯算法设计。

## 先做的三件事

1. **确认当前产物是哪一次构建的**。版本、比特流、硬件描述、模型、解码器五者是不是同一轮；
   这一条不通，后面所有现象都不能归因（见 D06、F01）。
2. **确认现象可重复**。同一输入、同一预热、同一计时边界下能不能重复出现；
   不能重复的，先解决测量方法本身（见 G02、C01）。
3. **确认缺什么**。工具版本、器件型号、板卡、驱动、权限——缺条件时先向上级要条件，
   不要在没有条件下反复重试（见 A01、A02、A04）。

## 按阶段找条目

| 阶段 | 先看这些 | 典型表现 |
| --- | --- | --- |
| 开工前 | A01–A06、B01–B07 | 环境没配好、边界没写、两边定义不一致 |
| 派活与协作 | B02、B03、B05、C03、C05 | agent 声称完成、一次改太多、用"应该"代替验证 |
| 综合与实现 | D01–D07 | 只有综合报告、负裕量、薄裕量、例外没审 |
| 上板 | E01–E07 | overlay 加载失败、DMA 无数据、花屏、读回 0 |
| 模型与数值 | F01–F05 | PT/ONNX 不同源、输出维度变了、预处理不一致 |
| 测量与结论 | G01–G06、H04 | 边界不同却相减、探针拖慢系统、平均值掩盖长尾 |
| 交付 | H01–H03 | 绝对路径、资产缺失、中文文件名 |

## 按症状找条目

| 你看到的现象 | 先查 | 第一个动作 |
| --- | --- | --- |
| 综合过了，板上一跑就错 | D01、H04 | 确认有没有实现后的时序与资源报告，没有就先补 |
| 时序裕量是正的小数（几十 ps） | D03 | 小于 50 ps 或小于周期的 1%，一律按薄裕量处理 |
| 板上画面花、错位、只有半帧 | E03、E02 | 先看 DMA 帧计数与帧长度，再看显示 |
| 寄存器读回 0 或某个恒定值 | E04 | 先按 HWH 与接口契约核对地址、偏移和读写属性；存在安全可读的身份寄存器时再核对其值 |
| 帧率比预期低 | E07、G02 | 先关掉诊断插件测一遍，排除探针自身开销 |
| 加了一个新功能之后帧率掉了 | E07、G02 | 先确认掉的是哪一段（采集/推理/绘制），再比新旧两版同一场景 |
| agent 说在推进，但没有任何文件变化 | C02 | 30 分钟内没有产出或有新日志就打断，要它先给中间产物 |
| 换了一个模型，结果全错 | F01、F02 | 先验 PT→ONNX→量化是不是同一份来源 |
| agent 说改完了，但行为没变 | B03、C04 | 要它给出改动前后的可核对证据（日志、哈希、报告） |
| 两个人对"通过"有分歧 | B07 | 把验收场景写成"给定输入→观察到什么→判定条件" |
| 上次的结论这次还能不能用 | G04、H04 | 查结论的模型/硬件/输入/计时边界是否一致 |
| 怎么跑都装不上工具 | A01、A02 | 先确认版本与器件是否装了，不要重装整包 |

## 一条经验的用法

1. 只做条目里给的区分实验，一次一个变量。
2. 实验结果要能落到文件上（日志、报告、哈希），口头结论不算。
3. 现象消失不等于问题解决：要能说清是哪一步改变的。
4. 现象与条目边界不符时换条目，不要把结论硬套。
5. 补充新条目时沿用同一格式：现象、触发、发现、定位、处理、边界。

## 什么时候停下来

- 三次尝试后现象没变：停下来写清已经排除了什么，换人或换条目。
- 缺条件（工具、板卡、样本）且无法补齐：停下来上报缺什么，不要继续在同一路径上重试。
- 需要器件手册或厂商确认：把已排除的项写清，转人工。

## 边界

- 条目来自真实工程失败，标的是"在那些工程里出现过"，不是"在任何工程里必然出现"。
- 关于 A03（路径带中文）：受影响的是 EDA 工具与脚本自己解析路径的场合（Vivado、部分 Tcl 与 .bat 包装器）。
  把技能包、文档、日志放在中文目录里通常没事，真正会失败的是把这些路径交给工具去打开或构建。
- 工具或框架大版本变化后，A、D、E 三类的具体命令可能失效，判断顺序仍然可用。
- 涉及具体器件、具体 IP、具体型号的坑不在覆盖范围，需要各自手册与实测。
