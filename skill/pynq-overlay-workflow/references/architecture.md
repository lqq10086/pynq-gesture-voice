# 架构与迁移

| 层次 | 常见职责 | 不作为通用前提 |
|---|---|---|
| Linux/PYNQ | 进程、文件、设备、Python 与 PL 管理 | 账号、解释器路径、Notebook、镜像 |
| PL | 稳定采集、并行计算、扫描和握手 | 固定 IP、参考时钟、引脚、极性 |
| PS Python | 复杂状态、调度、驱动和通信 | 原题业务模型 |
| 可选上位机 | 显示、记录或控制请求 | 必须用浏览器、以太网或 UART |

PYNQ 连接 Python 与可编程硬件，应用目录不是整个基础系统。SD 等介质保存源码和 bit/hwh；PL 配置断电后由启动流程重新加载。文件持久化与开机自启不同。

少量控制/状态可走 MMIO/AXI-Lite 类通路，AXI GPIO 是一种实现。持续大批量数据先算字节率、缓冲深度与访问成本，再选择 DMA/AXI 主接口；新任务按需裁剪旧视频或模型链路。

## 适配矩阵

| 变化 | 可复用 | 重新确认 |
|---|---|---|
| 同板换应用 | 环境核验、构建顺序、Overlay/IP 检查、验证方法 | PL、业务驱动、数据语义和入口 |
| 换板 | 契约结构、分层方法、公共 API 部分 | SoC/器件、PS/DDR/MIO、时钟复位、引脚电压、镜像和权限 |
| 换工具 | 源组织与验收指标含义 | Tcl、IP 版本、报告格式、导出与后端 |
| 换运输 | 状态语义与错误处理方法 | 带宽、帧边界、连接所有权、心跳、部署 |

Zynq-7000 的 PS7 preset/寄存器不能直接用于 UltraScale+。每板使用自己的 BD/PS 配置与 XDC。完整 Overlay 只有一个当前所有者，文件共存不代表两个完整 PL 应用同时运行。

## 工程落地

优先沿用已有目录。新工程可包含 hardware、overlay、app、scripts、config、reports 和 README。交付 RTL/XDC/BD/Tcl、应用、契约、同次产物与构建信息、启动停止和版本。镜像和工具链可另列来源。

驱动封装访问语义和初始化，业务不散写寄存器。配置区分应用参数、板级适配与硬件契约。外设编号、位序和极性需校准，资料网络名不能替代实体标签。

硬件采集、PS 调度、传输和绘制分别计时。事件保序并定义溢出策略；状态可合并。原子提交/双缓冲按一致性需求选择。toggle/ACK、FIFO POP、W1C 和 read-to-clear 都是具体协议，不是 PYNQ 统一行为。

Python 休眠不是硬实时保证。超时使用单调时钟；断线行为由应用定义。不同零点/位宽的 PL 与 PS 时间戳不能直接相减。FPS、纯线路计算和算法单项基准不是完整操作延迟。

## 条件分支 DMA

先确认驱动、AXI Stream 握手、TLAST、长度单位、对齐、DRE、通道顺序和内存端口。使用当前 PYNQ 支持的 allocate 缓冲，明确所有权与完成条件。非一致性缓存需在 PS 写后/PL 读前同步到设备，PL 写完成/PS 读前同步回来；先查驱动是否已自动处理。普通 NumPy 虚拟地址不能当设备地址。等待必须有当前驱动支持的超时/错误策略；缓冲释放必须等待传输完成或确认停止。本包不提供未在目标 IP 验证的 DMA 启停程序。
